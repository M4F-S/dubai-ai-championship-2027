## 4. Fabricated evaluation — M-08

`benchmarks/golden_eval.py` contains **no** `subprocess`, `os.system`, `requests`, `urllib` or `socket`
call. It never invokes `build/taryaq_agent`. The evaluation path is:

- `turn.get("simulated_tool_call")` (line 278)
- `run_ablation_simulation(...)` (lines 660, 918, 1125)

So the "240 trials / 30 tasks × 8" are Python simulation over scenario JSON. The report nevertheless
states "Measured Value", "Empirical 8-Trial Pass Rate", "Hardware Platform: Minisforum UM790 Pro", and
`pass^1 = pass^8 = 100.0%` with zero failures. For a real LLM-driven agent, 100% strict 8/8 consistency
would itself be suspicious; here it is simply not a measurement.

The ablation table is internally incoherent, which is diagnostic:

| Configuration | Task accuracy | p95 latency | Unsafe | Abstention |
|---|---|---|---|---|
| 7B alone | 36.0% | 754.0 ms | 41.0% | 0.0% |
| 7B + Laya | 74.5% | 748.4 ms | 5.5% | 14.5% |
| 7B + Laya + verifier | 88.0% | **202.1 ms** | 0.0% | 12.0% |

Adding two processing layers cannot reduce p95 latency by 73%. And a 7B model at ~19.9 tok/s cannot
perform prompt prefill plus a tool call in 754 ms — that is roughly 15 generated tokens with zero
prefill. The table cannot have come from a run.

**The traceability problem is now worse than before.** `docs/NUMBER_TRACEABILITY_MATRIX.md` maps each
deck number to `bench/results.json` or `GOLDEN_EVAL_REPORT.md`, and
`tests/test_submission_traceability.py` passes 8/8. The test is green because fabricated numbers trace
cleanly to fabricated files. Traceability of invented data manufactures confidence; it does not create
evidence.

## 9. Why this happened (and the rule that prevents it)

The project is now generating the *artefacts of evidence* faster than the evidence: a benchmark report
without a benchmark, an evaluation without an execution, a pilot without a partner, a traceability
matrix that traces invented numbers to invented files. Each artefact is internally consistent, which
makes the whole look stronger than the sum of its parts — and that is exactly the failure mode a strict
reviewer is looking for.

**Rule for the remaining ten weeks: build → measure → write. Never write → generate → claim.**
No document may contain the words "measured", "empirical" or "executed" unless a raw log, a command,
a date and a machine are attached.
